Core Concept

What Is a Semantic View?

A Semantic View is a Snowflake object that sits on top of physical tables and provides a business-friendly abstraction layer.

Instead of writing raw SQL with joins, filters, and aggregations, users (and AI agents) query using business concepts. Snowflake translates those into optimized SQL automatically.

No SQL needed Consistent metrics AI-ready

Without Semantic View

SELECT AVG(f.LANDED_COST) FROM GLD_FACT_PROCUREMENT f JOIN GLD_DIM_SUPPLIER s ON f.SUPPLIER_KEY = s.SUPPLIER_KEY GROUP BY s.SUPPLIER_COUNTRY...

With Semantic View

"What's the average landed cost by supplier country?"

Semantic View

The 7 Building Blocks

📋

1. Tables

Physical tables exposed with aliases. Define what data is available.

🔗

2. Relationships

Join paths between facts and dimensions. Define how tables connect.

🔢

3. Facts

Raw numeric columns — the "atoms" that get aggregated into metrics.

📐

4. Dimensions

Categorical columns for slicing and grouping: the "by" in every question.

📊

5. Metrics

Pre-defined aggregations (SUM, AVG, etc.) ensuring consistent definitions.

🏷️

6. Synonyms

Alternative names so the AI understands "vendor" = supplier, "spend" = cost.

🤖

7. AI Instructions

Free-text directives guiding LLM behavior and SQL generation.

Synonyms — Bridging Natural Language

Users don't always use exact column names. Synonyms map business language to the right data.

User SaysResolves To

"vendor"dim_supplier table
"freight cost"total_shipping metric
"cheapest option"min_landed_cost metric
"shipping method"transport_mode dimension

"Tariff & procurement intelligence for a US manufacturer sourcing globally. Analyze landed costs, tariff impacts, supplier optimization."

"Models a US manufacturer buying parts globally. Landed cost = part cost + tariff + shipping. Product categories: Electronics, Appliances, Industrial, Automotive. Round to 2 decimals."

AI_QUESTION_CATEGORIZATION

"Redirect unrelated questions. Clarify if user wants current vs historical tariffs."

AI Layer

Cortex Agent — TARIFF_AGENT

The Cortex Agent is the conversational interface. Users ask questions in natural language and the agent uses the Semantic View to generate and execute SQL.

CREATE OR REPLACE AGENT TARIFF_AGENT FROM SPECIFICATION $$ models: orchestration: auto tools: - tool_spec: type: cortex_analyst_text_to_sql name: tariff_intelligence_agent tool_resources: tariff_intelligence_agent: semantic_view: DEMO_INTELLIGENCE.TARIFF .SV_TARIFF_INTELLIGENCE $$;

How It Works

1. User asks a question

"Show me top 5 countries by total tariff cost"

2. Agent reasons with LLM

Picks the text-to-SQL tool and maps concepts to semantic view elements

3. SQL is generated

Using metrics, dimensions, relationships, and AI instructions

4. Results returned

Clean, formatted answer with the underlying SQL visible
